# Preference Learning

Use this skill when the system should learn from the user's corrections, approvals, repeated choices, or workflow patterns.

## What can be learned

- Writing voice preferences.
- Phrases the user likes or rejects.
- Prohibited punctuation or style patterns.
- Preferred assignment folder names.
- Preferred file naming style.
- Preferred review times.
- Preferred source types.
- Common professor instructions.
- Repeated rubric weaknesses.
- Usual drafting pace.
- How early the user wants work ready.

## Evidence standard

Treat a preference as learned only when at least one of these is true:

- The user explicitly states the rule.
- The user corrects the same issue more than once.
- The user approves a final draft that clearly demonstrates the pattern.
- The rule appears in course instructions or professor feedback.

Do not learn from one accidental draft, one temporary workaround, or an unapproved AI output.

## Memory shape

Store learned rules as plain language records with:

- Rule.
- Source of the rule.
- Date learned.
- Confidence level.
- Where it applies.
- Whether user approval is needed before applying it.

## Applying learned rules

When applying learned rules:

- Prefer the most recent explicit user instruction.
- Prefer current assignment instructions over older general preferences.
- Preserve conflicts instead of hiding them.
- Tell the user when a learned rule changed the output in a meaningful way.

## Forget or revise

If the user corrects a learned rule, update the rule and do not argue with the older pattern.
